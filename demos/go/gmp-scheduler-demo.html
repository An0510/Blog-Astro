图例 · Legend

G · Goroutine 用户态轻量任务（像很多小任务单）。栈很小，由 Go runtime 调度，不是一 G 一 OS 线程。
P · Processor 逻辑处理器：手里有本地可运行队列。GOMAXPROCS 大致决定 P 的数量。
M · Machine 真正的 OS 线程。必须绑定一个 P 才能跑 Go 代码；G 跑在「M+P」上。
CPU Core 硬件核。M 最终在某个核上执行机器指令。

对照直觉（JS）

  • 浏览器常是单线程事件循环；Go 用多个 M 真正并行。
  • go f() ≈ 丢一张新任务单 G 进队列，不是立刻新开 OS 线程。
  • channel / 阻塞系统调用时，G 可卸下，M/P 换别的 G 继续干。
  • 本地队列空了 → 从 Global Queue 拿，或 Work Stealing 偷别的 P 的一半。
