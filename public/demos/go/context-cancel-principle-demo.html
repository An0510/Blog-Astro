context 取消原理：不是魔法杀进程

核心：cancel() → 关闭 Done channel → 听的人自己停。 对照 JS：像 AbortController 的 signal，不是 kill(-9)。

原理三句话

  • WithCancel 造出一对：ctx + cancel。
  • cancel() 的实质是关闭该 ctx 的 Done channel（可广播给所有接收者）。
  • 子 context 挂在父上：父取消 → 子也取消（向下传播）。
WithCancel cancel Done select ctx.Err 传播

协作式，不是强杀

运行时不会因为 cancel 就干掉 goroutine。你的代码必须：

  • select 里带 <-ctx.Done()，或
  • 循环里查 ctx.Err() != nil

不听的「聋子」会继续跑——对照 JS：不读 AbortSignal 的 fetch 辅助逻辑也不会停。

go-mini-api 里的 maybeSleep： select 同时听 timer.C 和 r.Context().Done()； 客户端超时 → Done 关闭 → 立刻 return err，不再傻等。

练习：curl '.../items?sleep=5000' --max-time 1
