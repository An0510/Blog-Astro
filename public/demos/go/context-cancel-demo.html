关键字对照

        
    
          
  • context.Background()：根上下文，程序起点常用它当父。
    • 
          
  • WithCancel(parent)：派生出子 ctx + cancel 函数。
    • 
          
  • cancel()：关闭该 ctx 的 Done，通知所有监听者。
    • 
          
  • <-ctx.Done()：收到取消/超时就可读。
    • 
          
  • select：同时听 Done 和干活分支。
    • 
          
  • defer cancel()：main 返回前再 cancel 一次，防泄漏（多次调用安全）。

和 WaitGroup 分工

        
context = 发「停」的信号；WaitGroup = 等「人退完」。常一起用：先 cancel，再 Wait。

      

    


    

      
实际场景扩充

      

        

          
① HTTP 请求超时

          
网关给每个请求挂 context.WithTimeout。超时后自动 cancel，下游查库 / 调 RPC 的 goroutine 在 select 里听到 ctx.Done() 就停，避免请求已断开还白干活。

        

        

          
② 用户取消上传

          
用户点「取消」→ 调用 cancel() → 上传 worker、分片校验 等子 goroutine 都听同一个 ctx，一起退出；父函数里的 defer cancel() 保证异常路径也会关掉。

        

        

          
③ 父任务取消一串子任务

          
一个订单处理拆成「风控 / 库存 / 通知」多个 worker，共用派生 ctx。风控失败就 cancel，其余还没做完的直接收工，而不是各跑各的。

        

        

          
④ 对照本页示例代码

          
Background → WithCancel 得到可取消的孩子；worker 在 default 里假装干活，同时盯着 Done；main 调 cancel() = 广播停工；defer cancel() = 离开前再确认关干净。
